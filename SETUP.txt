Nexa AI setup
=============

LOCAL PREVIEW
1. Copy `.env.example` to `.env` in this folder.
2. Add the Groq key to GROQ_API_KEY. GEMINI_API_KEY is optional and is used as backup.
3. Double-click `Start-Nexa.cmd` to start the server and open Nexa in your browser. Keep the server window open while using the app.
4. Or open PowerShell in this folder, run `npm.cmd start`, then open http://localhost:3000

GOOGLE LOGIN
1. In Google Cloud Console, create a project and set up Google Auth Platform / OAuth consent screen.
2. Create an OAuth Client ID with application type Web application.
3. Add `http://localhost:3000` as an Authorized JavaScript origin.
4. Put the Web Client ID in `.env` as GOOGLE_CLIENT_ID. Keep the project owner as sourabh73003@gmail.com.
5. Restart Nexa. Google login is activated whenever GOOGLE_CLIENT_ID is set.

Owner login is determined only from a verified Google ID token. Other signed-in users can chat; the app has no public settings or feature-editing endpoint. Source and feature changes stay under the private GitHub/Render accounts.

PUBLIC DEPLOY (Render)
A Render account and a private GitHub repository connected to Render are needed for a public URL.
1. Add your deployed website origin to the OAuth Client's Authorized JavaScript origins (for example, the final onrender.com URL).
2. In Render, create a Blueprint from the private repository; Render reads `render.yaml`.
3. Enter GOOGLE_CLIENT_ID and GROQ_API_KEY as secret values. GEMINI_API_KEY is optional. SESSION_SECRET is generated by Render.
4. Select the Free instance and deploy. Users sign in with Google; sourabh73003@gmail.com gets the owner role.

Render Free services may sleep after 15 minutes without visits and take about a minute to wake. If free usage limits are exceeded and no payment method is on file, Render suspends service/builds rather than charging for overages. Free AI providers have their own quotas.

WORKSPACE FEATURES
==================
- Start separate conversations with New chat; Ctrl+K (or Cmd+K) starts one quickly.
- Chat history is saved in this browser and kept separate for each signed-in email. It does not sync across devices yet.
- Choose Auto to use Groq first and Gemini as a backup, or pick Groq GPT-OSS 20B or Gemini 3.8 Flash. One key per provider can access its permitted models; duplicate keys do not bypass provider quotas.
- Quick answer and Deep thinking change the instructions sent to the AI.
- Attach accepts text, Markdown, CSV, and JSON files up to 10,000 characters, or PDF and PNG/JPG/WEBP files up to 3 MB (PDF and image analysis use Gemini).
- Web search uses Groq browser search or Gemini Google Search grounding and shows source links. Search usage can consume provider quota and may be billable, depending on the provider and account tier.
- AI replies stream into the chat and render common Markdown, headings, lists, and code blocks.
- Stop ends an in-progress response. Edit and regenerate controls are available for the latest text-only exchange.
- Voice input uses the browser's speech recognition support and microphone permission.
- Chat requests have a per-process guard of 20 per minute and 200 per day per account/IP. These counters reset when the server restarts and are not shared across multiple server instances.

CURRENT STORAGE LIMIT
=====================
Chat history is stored in the current browser's local storage. It survives refreshes on that browser but does not sync across devices. Uploaded PDF/image contents are kept only in memory for the active page and are not saved with history. Cross-device history and robust shared quota enforcement need a configured database/cache service and migration work before a public multi-instance deployment.

PRODUCTION NOTES
================
- Configure persistent SESSION_SECRET, Google OAuth origin, and provider keys as deployment secrets. Never commit `.env`.
- Google Search grounding and provider search/model calls consume provider quota; check provider billing and quotas before enabling them for a public audience.
- The app is ready for a local authenticated preview. A dependable public multi-user launch still needs persistent session-secret configuration, shared rate-limit storage, and a privacy-reviewed database if cross-device history is required.
